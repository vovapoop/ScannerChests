# Автоопределение границ сундука (кнопка «Автоопределение»)

## Цель

Добавить кнопку «Автоопределение», которая один раз определяет прямоугольник сетки
открытого сундука на скриншоте и сохраняет его в `config.json` (аналог ручной
калибровки кликами, но без участия пользователя). Прямоугольник ищется по
характерной регулярной сетке ячеек сундука Minecraft.

## Текущее состояние

- Границы сетки задаются вручную: `calibrate_grid_interactive()` в
  `chest_scanner/scanner/grid.py` или координаты в настройках
  (GUI: `chest_scanner/gui/settings.py`, пункт панели в
  `chest_scanner/gui/main_window.py`).
- `chest_grid` в `config.json`: `x1, y1, x2, y2, columns, rows` в координатах
  `reference_screen_size` (по умолчанию 1920×1080), масштабируется в
  `get_grid_rect()` под текущее разрешение.
- Открытый сундук детектируется шаблоном `chest_is_open()` — сам прямоугольник
  сетки от шаблона не зависит.
- Пресеты: двойной сундук 9×6, одиночный сундук 9×3
  (`columns`/`rows` хранятся в конфиге).
- Дополнительно:
  - существующий пресет «Шалкер (9×3)» в GUI переименовывается в
    «Одиночный сундук (9×3)» (`chest_scanner/gui/settings.py`);
  - пресет «Инвентарь (9×4)» удаляется полностью вместе со всеми упоминаниями
    9×4 (`chest_scanner/gui/settings.py`, `chest_scanner/gui/help.py`, README);
  - справка и README обновляются соответственно.

## Требования пользователя

1. Кнопка «Автоопределение» — однократно определяет границы и сохраняет их в config.
2. Сначала используется текущий пресет (columns × rows из config) с проверкой, что
   внутренняя сетка ему соответствует; при несовпадении — запасной режим
   автоопределения columns/rows по проекциям.
3. Пользователь предоставил реальные скриншоты в `tests/screenshots/`:
   двойной сундук 9×6 и одиночный сундук 9×3 — в пустом и заполненном виде
   (4 файла). Файлы переименовываются в латиницу при реализации:
   - `double_chest_9x6_empty.png`, `double_chest_9x6_filled.png`;
   - `single_chest_9x3_empty.png`, `single_chest_9x3_filled.png`.
4. Сундуков 9×4 не бывает: пресет «Инвентарь (9×4)» и все упоминания 9×4
   удаляются.

## Архитектура решения

### 1. `detect_grid_rect(screen)` в `chest_scanner/scanner/grid.py` (`GridMixin`)

Возвращает `{"x", "y", "width", "height", "columns", "rows"}` или `None`.

Алгоритм:
1. Градации серого → `cv2.Canny` → морфологическое закрытие для соединения линий ячеек.
2. Выделение горизонтальных и вертикальных линий длинными морфологическими ядрами.
3. `cv2.findContours` по линиям → кандидаты-прямоугольники:
   - фильтр по минимальной/максимальной площади (относительно экрана);
   - фильтр по прямоугольности (approxPolyDP: 4 угла, углы ≈ 90°);
   - фильтр по соотношению сторон (ожидание: width/height ≈ columns/rows с допуском).
4. Верификация каждого кандидата проекционным методом:
   - внутри кандидата суммируем вертикальные/горизонтальные линии по осям;
   - ищем регулярные пики (границы ячеек); количество ≈ columns+1/rows+1 (допуск ±1);
   - шаг пиков регулярен (std шага ниже порога) — отсечение ложных срабатываний.
5. Точные координаты x1/y1/x2/y2 берутся по позициям крайних пиков, а не по контуру.

Если пресет не подтвердился — см. п. 2.

### 2. Запасной режим: автоопределение columns/rows

- По найденному прямоугольнику-кандидату считаем число вертикальных/горизонтальных
  пиков: columns = пики_верт − 1, rows = пики_гор − 1.
- Проверяем регулярность шага; диапазоны допустимости: columns 1–18, rows 1–12.
- Финальная повторная проверка верификацией.

### 3. Обёртка `auto_detect_grid()` (рядом с `detect_grid_rect`)

Порядок действий:
1. Скриншот (`screenshot_bgr`).
2. Если шаблон сундука есть и `chest_is_open(screen)` == False → ошибка
   «Сундук не открыт» (для первого запуска шаблона может не быть — проверка
   пропускается, сетка всё равно ищется).
3. `rect = detect_grid_rect(screen)`; если `None` → ошибка «Не удалось обнаружить сетку».
4. Пересчёт координат в `reference_screen_size`: `x1_ref = round(x1 * ref_w / sw)` и т.д.
5. `self.grid` (= новый `chest_grid` с columns/rows из rect), обновление
   `self.config["chest_grid"]` и `save_json(paths.CONFIG_FILE, self.config)`.
6. Автогенерация шаблонов (`auto_generate_templates(force=False)`) — как в
   ручной калибровке.
7. Возврат rect (для логирования/отладки).

### 4. GUI

- `chest_scanner/gui/settings.py`: кнопка «Автоопределение» рядом с
  «Калибровка кликами» (`_safe_calibrate`), метод `_safe_auto_detect_grid`.
- `chest_scanner/gui/main_window.py`: пункт панели «Сетка (авто)» рядом с
  «Калибровка», метод `_auto_detect_grid`.
- После успеха: лог + показ отладочного окна сетки (`show_grid_debug`) для
  визуальной проверки результата.
- При ошибке: понятное сообщение (сундук не открыт / сетка не найдена).

### 5. Тесты `tests/test_grid_detect.py`

- Хелпер генерации синтетической сетки сундука (фон, рамка, ячейки; часть ячеек
  заполнена цветными «предметами»; параметры: columns, rows, cell_size, offset).
- `test_detect_rect_9x6` — пресет 9×6, точность ±2 px.
- `test_detect_rect_9x3` — пресет одиночного сундука.
- `test_detect_scaled_4k` — изображение 3840×2160 (проверка масштабирования).
- `test_detect_with_items` — заполненные ячейки не мешают поиску.
- `test_detect_no_chest` — экран без сетки → `None`.
- `test_auto_rows_columns_fallback` — пресет не совпадает, rows/columns
  определяются проекциями.
- Проверка сохранения масштабированных координат через GridStub-подобный стенд
  (как в `tests/test_grid_workflow.py`).

### 5a. Интеграционные тесты на реальных скриншотах `tests/screenshots/`

- Файлы (переименовываются из кириллических имён при реализации):
  - `double_chest_9x6_empty.png` / `double_chest_9x6_filled.png` — двойной сундук 9×6;
  - `single_chest_9x3_empty.png` / `single_chest_9x3_filled.png` — одиночный сундук 9×3.
- Параметризованный тест: для каждого файла `detect_grid_rect` должен найти сетку
  с ожидаемыми columns/rows (точность координат не проверяется — прямоугольник
  сверяется через верификацию и визуально отладкой).
- Дополнительно: на найденных слотах пустой сундук должен давать низкую
  дисперсию между слотами (косвенная проверка совпадения с реальной сеткой).
- Если файлов нет — `pytest.skip` (тесты не ломают CI, скриншоты в репозитории).
- Скриншоты используются также для ручной проверки через отладочное окно сетки.
