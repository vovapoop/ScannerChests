# История версий

## 1.9.1 (2026-10-30)

### Исправление ложной детекции открытого сундука

- **Сканирование больше не срабатывает при закрытом сундуке** и на других
  интерфейсах (инвентарь игрока, другие контейнеры): к шаблонному матчингу
  добавлена геометрическая проверка — шаблон заголовка сундука обязан быть
  найден в узкой полосе непосредственно над настроенной сеткой. Матчи в
  любом другом месте экрана отклоняются, даже при высокой корреляции.
- **Порог шаблона сундука поднят с 0.82 до 0.88** (`chest_template_threshold`).
  Значение 0.82 в существующих конфигах автоматически мигрирует на 0.88 при
  первом запуске; явно настроенный пользователем порог не изменяется.
- **Автоскан стал быстрее и надёжнее**: проверка «сундук открыт» захватывает
  и анализирует только зону вокруг ожидаемой позиции заголовка вместо всей
  области вокруг сетки.
- **Диагностика в лог**: при каждой проверке в `logs/scanner.log` (уровень
  DEBUG) пишутся оценка корреляции, координата матча, допустимая зона и
  порог — любое отклонение легко объяснить по логу.

## 1.9.0 (2026-10-29)

### Новый интерфейс на Qt (PySide6)

- **Tkinter полностью удалён** из проекта. GUI переписан на PySide6 (Qt):
  `QMainWindow`, современные виджеты, единая тёмная тема через QSS
  (`chest_scanner/gui/theme.py`).
- **Системный трей встроенный в Qt** (`QSystemTrayIcon`): зависимость
  `pystray` больше не нужна. Меню, уведомления и опция «сворачивать
  в трей» сохранены.
- **Надёжное обновление UI из фоновых потоков** через сигналы/слоты
  (безопаснее, чем `root.after`).
- Диалоги переписаны как классы `QDialog`: мастер первого запуска,
  неизвестный предмет, история с фильтрами и сравнением, экспорт,
  профили, статистика, база предметов с CRUD.
- Настройки: навигация «разделы слева — страницы справа»,
  слайдеры с подписью значения, предпросмотр шаблонов.
- Зависимость: `PySide6-Essentials` (QtCore/QtGui/QtWidgets) вместо
  метапакета `PySide6` — меньше размер установки и сборки.
- PyInstaller-сборка (`ChestScanner.spec`) использует встроенные хуки
  PySide6; QtWebEngine/Addons исключены из бандла.

## 1.8.0 (2026-10-29)

### Распознавание: быстрее и точнее

- **pHash-индекс предметов** — грубый отбор кандидатов по перцептивному
  хэшу (DCT, 64 бита) вместо полного перебора иконок: сканы с большой
  базой выполняются в разы быстрее. Порог отбора — `phash_threshold`
  (настройка «Распознавание», по умолчанию 14).
- **Кэш распознавания** по хэшу иконки слота: повторные сканы одинаковых
  иконок не пересчитываются (`item_detect_cache`, по умолчанию включён).
- **CLAHE-предобработка** иконок (нормализация яркости в LAB) повышает
  устойчивость pHash к освещению и гамме.
- Унифицирован рабочий путь распознавания: единый двухуровневый
  `detect_item` (pHash → точный SSIM+гистограмма) вместо дублирующих
  `_compare_with_db`/`detect_item`.
- **OCR количества**: поиск цифр с двумя порогами маски (жёсткий/мягкий),
  разделение слипшихся цифр по вертикальному профилю, поддержка значений
  до 999999.

### Горячие клавиши без прав администратора

- Новый модуль `chest_scanner/hotkeys.py`: глобальные хоткеи через
  WinAPI `RegisterHotKey` (message-only окно). **UAC больше не требуется**.
  При недоступности — автоматический фоллбэк на прежний polling
  (библиотека `keyboard`).

### Надёжность данных

- Атомарная запись JSON (`tmp` + fsync + `rename`) во всех сохраняемых
  файлах — повреждение при сбое исключено.
- Автоархивация `results/chests.json` в `results/history` при превышении
  2 МБ.
- Защита путей иконок от path traversal при импорте/нормализации базы.
- SQLite-копия результатов (`results/chests.db`) для аналитики и резерва
  (модуль `chest_scanner/storage.py`).

### Интерфейс

- Иконка в системном трее с меню и уведомлениями; опция «сворачивать в
  трей при закрытии окна».
- Блок «Последний скан» в главном окне с иконками предметов.
- Диалог «Статистика» (кнопка в панели инструментов): топ предметов по
  количеству и частоте (на базе SQLite).
- Пресеты сетки в настройках: двойной сундук 9×6, шалкер 9×3,
  инвентарь 9×4.

### Тесты и процессы

- Новые тесты: pHash и предобработка, конфиг, сетка, автоархивация,
  экспорт, разбиение Discord-сообщений, SQLite-хранилище, парсинг
  горячих клавиш (всего 38 тестов).
- `requirements-dev.txt` (pytest, ruff), профиль линтера `ruff.toml`,
  GitHub Actions CI (линтинг + тесты на Python 3.10–3.12).

## 1.7.1 (2026-10-29)

### Новое: отдельное приложение владельца + зашитые адреса базы

- **Приложение владельца `OwnerApp.exe`** (`owner_app/`): hub-сервер с журналом
  выгрузок (время, peer_id, размер), полный CRUD объединённой базы и публикация
  на GitHub. Сборка — `build_owner.bat`, `OwnerApp.spec`, установщик
  `installer_owner.iss`. Секреты (токен GitHub, ключ hub) — в `owner_secret.json`
  рядом с exe, в код не зашиваются.
- **Адреса зашиты в клиент**: единый файл [`chest_scanner/builtin_sync.py`]
  (репозиторий и адрес hub с плейсхолдерами) подставляется в `DEFAULT_CONFIG`
  (`github_db`). Пользователям-клиентам больше ничего настраивать не нужно.
- **Клиентский сканер упрощён**: hub-сервер, окно «Публикация» и CRUD базы
  перенесены в приложение владельца; в сканере «База предметов» — только
  просмотр. В настройках вкладка «Общая база» — без полей ввода адресов.
- **Журнал выгрузок hub**: клиенты шлют заголовок `X-Peer-Id`, hub пишет
  `upload_log.json` (хранится последние 500 записей).
- Общая view-логика базы вынесена в `chest_scanner/gui/item_db_view.py`
  (режимы «просмотр» для сканера и «CRUD» для владельца).

### Тесты

- `tests/test_builtin_sync.py` — зашитые адреса в DEFAULT_CONFIG и валидация.
- `tests/test_owner_config.py` — owner_secret.json, приоритеты и roundtrip.
- `tests/test_hub.py` — добавлен тест журнала выгрузок.

## 1.7.0 (2026-10-29)

### Новое: общая база предметов через GitHub + hub (без сервера)

Серверная онлайн-база (`server/`, `chest_scanner/online.py`) удалена. Вместо неё —
распределённая синхронизация:

- **CRDT-фундамент** (`chest_scanner/sync/`): каждый предмет — запись с `updated_at`
  и `peer_id` (LWW), иконки контент-адресуются по sha256 (дедупликация).
  Слияние любых двух баз сходится без конфликтов (коммутативность и
  ассоциативность покрыты тестами).
- **GitHub-публикация**: каноническая база — Release с архивом `items-db.zip`
  (items.json + иконки). Клиенты скачивают последний релиз и сливают с локальной
  базой; владелец публикует новые версии по кнопке «Опубликовать на GitHub…».
- **Hub-режим (ПК владельца)**: локальный HTTP-сервер принимает выгрузки клиентов
  (`POST /api/upload`), объединяет их по CRDT, опциональный общий ключ `X-Hub-Key`.
- **Выгрузка «при возможности»**: изменения копятся в очереди `pending_upload.json`
  и отправляются на hub, как только он станет доступен (debounce 5 сек).
- **GUI**: вкладка «Общая база (GitHub)» в настройках (репозиторий, адрес hub,
  ключ, токен), кнопка «Обновить базу» и индикатор состояния в главном окне,
  окно «Публикация» с тегом релиза и черновиком.
- Конфигурация — блок `github_db` в `config.json` (по умолчанию выключено).
- Подробности: раздел «Общая база (GitHub)» в `README.md`,
  план — `plans/github-db-plan.md`.

### Тесты

- `tests/test_sync_crdt.py` — 14 тестов CRDT-слияния (LWW, tombstone, OR-set иконок,
  контент-адресация, свойства merge).
- `tests/test_github_sync.py` — 14 тестов GitHub-клиента (релизы, zip, публикация).
- `tests/test_hub.py` — 7 тестов hub-режима (health, приём zip, merge, ключ, publish).
- `tests/test_hub_client.py` — 8 тестов клиента выгрузки (очередь, ретраи, e2e).
